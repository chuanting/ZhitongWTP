# NetAILLM · 无线网络流量预测平台

基于 Chronos-2 时序基础模型的无线流量预测演示与评估控制台。加载内置示范小区或上传自己的
CSV，选择指标与预测窗口，一键得到概率预测、真实值对比与完整的时序评估指标。

```
┌── 数据源 ──┐ ┌────────── 指标卡 · MASE / MAPE / MAE / RMSE / R² / 覆盖率 ──────────┐
│ 7 个示范小区│ │                                                                    │
│ CSV 上传    │ │  全历史概览条（当前窗口位置）                                       │
├── 预测配置 ─┤ │  主图：历史上下文 │ 预测起点 │ 预测中位数 + 区间 + 真实值 + 基线      │
│ 指标 / 步长 │ │  逐步残差 · 其他指标小多图 · 指标明细表（模型 vs 季节朴素基线）       │
│ 上下文 / 区间│ └──────────────────────────────────────────────────────────────────┘
│ 预测起点    │
└────────────┘
```

### 切换到微调权重

后端默认加载基座 `amazon/chronos-2`，界面右上角会显示「基座模型」徽章。指向你自己的
微调产物即可切换，加载方式与 `03_predict.py` 一致，无需改代码：

```bash
NETAI_MODEL_PATH=/abs/path/to/Zhitong_SDU_WT_LLM ./run.sh
```

相对路径也能用（会依次按「当前目录 → 项目根目录 → backend 目录」查找），但**推荐绝对路径**：
服务进程的工作目录是 `backend/`，相对路径容易指偏，而 Hugging Face 会把找不到的本地路径
当成 repo id，报出 `HFValidationError: Repo id must use alphanumeric chars...` 这种看不懂的错。
现在目录不存在时会在启动阶段就直接报错并列出尝试过的位置。

权重目录里如果有 `04_finetune.py` 写出的 `finetune_meta.json`，界面底部会展示微调溯源信息
（LoRA 秩、训练序列数、步数、学习率、训练窗口）。

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `NETAI_MODEL_PATH` | `amazon/chronos-2` | 微调权重目录或 HF repo id |
| `NETAI_MODEL_LABEL` | `NetAILLM` | 界面显示的模型名 |
| `NETAI_DEVICE` | `cpu` | `cpu` / `cuda` / `mps` |
| `NETAI_PORT` | `8010` | 服务端口 |

> Apple Silicon 上 CPU 推理已足够快（24 步 × 8 通道约 0.15 秒），且 MPS 上部分算子会回落，
> 因此默认 `cpu`；在 CUDA 机器上设 `NETAI_DEVICE=cuda`。

## 内置数据集

取自 `licheng_5g.db`（济南历下区 5G 小区，小时级），按场景挑选 7 个覆盖不同流量形态、
频段与厂商的小区，每个含 8 个指标：

| 数据集 | 场景 | 频段 | 时间范围 | 点数 |
|---|---|---|---|---|
| 高校基站 | 高校 | 2.6G | 2025-07-24 ~ 2026-04-30 | 6,722 |
| 写字楼基站 | 写字楼 | 2.6G | 同上 | 6,722 |
| 地铁站基站 | 地铁 | 2.6G | 2025-10-16 ~ 2026-04-30 | 4,719 |
| 医院基站 | 医院 | 2.6G | 2025-07-24 ~ 2026-04-30 | 6,722 |
| 居民区基站 | 低层居民区 | 2.6G | 同上 | 6,722 |
| 商业中心基站 | 商业中心 | 4.9G（中兴） | 同上 | 6,722 |
| 城区广覆盖站 | 城区 | 700M | 2025-06-01 ~ 2026-04-30 | 8,016 |

（原始值为 0–1 比例，界面按 % 显示），平均有效连接数。

## 上传自己的数据

CSV 需要一列时间和至少一列数值指标，最多 8 个指标列：

```csv
timestamp,flow,uflow,dflow
2026-04-01 00:00:00,2.51,0.32,2.19
2026-04-01 01:00:00,2.18,0.29,1.89
```

- 时间列名支持 `timestamp` / `time` / `date` / `datetime` / `dt` / `时间` / `日期`，
  也会自动探测非标准列名；格式支持 ISO 字符串与 `2026043012` 这类 `YYYYMMDDHH` 整数。
- 编码支持 UTF-8（含 BOM）、GB18030、UTF-16。
- 采样粒度自动推断（分钟 / 15 分钟 / 30 分钟 / 小时 / 天 / 周），缺失时间点补齐为空值并在界面提示。
- 上限：32 MB、20 万行、8 个指标列。

## 评估口径

预测起点之后的 H 个点为预测窗口。起点落在历史范围内时是**回测评估**（有真实值可比对），
起点取到序列末尾时是**未来外推**（无真实值，不计算指标）。

| 指标 | 含义 |
|---|---|
| MAE / RMSE / 偏差 | 与指标同量纲；RMSE 对大偏差更敏感，偏差为正表示系统性高估 |
| MAPE / sMAPE | 百分比误差；MAPE 会剔除接近零的观测点（低于序列均值 1%），剔除比例在界面给出 |
| MASE | 以季节朴素法为 1.0 的标准化误差，跨小区、跨量纲可比；< 1 即优于基线 |
| WQL | 加权分位数损失，衡量整个预测区间的概率质量，越小越好 |
| R² / 相关系数 | 预测解释了多少真实波动 |
| 区间覆盖率 | 真实值落入预测区间的比例，理想情况接近名义水平（如 80%） |

**对照基线**为季节朴素法（`ŷ(T+h) = y(T+h−m·⌈h/m⌉)`，小时数据 m=24），即"用上周期同一时刻的值"，
是流量预测里通行的最低参考线。指标卡上的 ↓x% 即相对该基线的误差降幅。

预测区间来自模型输出的分位数（默认 P10–P90），是不确定性估计，不是保证范围。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health`、`/api/model` | 服务与模型状态（权重路径、设备、是否微调、加载耗时） |
| GET | `/api/datasets` | 数据集目录与默认参数 |

## 公网部署相关

默认配置是**本机 demo**：只监听 `127.0.0.1`、不鉴权、上传文件不过期。对外开放前
至少要设 `NETAI_ACCESS_PASSWORD`（共享访问口令）和 `NETAI_COOKIE_SECURE=1`，
完整清单见 [DEPLOY.md](DEPLOY.md)。应用内置：

- 共享口令鉴权（HMAC 签名 Cookie，默认 7 天有效）
- 分级限流：登录 10 次/5 分钟、预测 30 次/分钟、上传 20 次/小时（按来源 IP）
- 推理有界排队：同时只跑一个推理，等待超过 `NETAI_MAX_QUEUE` 直接返回 503 而非无限堆积
- 上传数据自动清理：默认保留 24 小时、目录上限 512 MB，超出按最旧优先淘汰

## 数据可信区间

内置数据集源自运营商导出，**末尾 223 个小时（2026-04-21 16:00 之后）是前一周的
逐字复制**——属于补齐数据而非真实观测。落在该区间的回测毫无意义，因为模型在
上下文里已经逐字见过"未来"。

`backend/app/dataquality.py` 会自动检出这类整周期复制：

- 默认预测起点自动避开复制段
- 手动选到该区间时界面明确告警
- 上传的数据同样会被检查，结果在数据集列表里以「数据存疑」角标提示

判定标准是**所有通道同时**与整数个季节周期前逐位精确相等，且连续长度 ≥ 12 个点，
真实流量几乎不可能触发。

## 说明

- 所有推理在本机完成，上传的数据不会发送到外部服务。
- 图表配色为经过 CVD（色觉障碍）模拟校验的三色方案，深浅两套主题分别取色；
  颜色始终与文字图例同时出现，识别不依赖颜色本身。
- 不同量纲的指标一律走小多图各自独立纵轴，不使用双纵轴。
